## 안건 2: 서비스 아키텍처 및 기술 스택 확인

**논의 요약:**
- **서비스 구성:** 카메라 → VPN 터널 → 플랫폼 저장 → 스트리밍 서버 → 고객(앱/PC/웹)
- **보안:** 카메라 내장 VPN(SSL VPN, PUF VPN)으로 보안 터널링 구성
- **영상 분석:** 침입감지가 메인 기능(전체 카메라의 10% 사용), GPU 5대로 객체 검출
- **외부 연동:** 
  - 아이디(청약정보 수신, 전용선)
  - 우리가게패키지(인터넷)
  - 출입문관리기(전용선)
  - SMS게이트웨이(API, 전용선)
  - 에스원(출동서비스, VPN)
- **개발 언어:** C(메인), Java 1.8, JavaScript 40%, 기타
- **OS:** CentOS 7.4 (EOS 대상)
- **DB:** MariaDB 10.x 초반 (EOS 대상)
- **WAS:** Tomcat 7.x (EOS 대상)
- **서버 형태:** 전체 물리서버(Physical)

**결정사항:**
- 3-Tier 아키텍처가 아닌 영상 처리 특화 구조로 확인됨
- 계층 구조는 추후 물리 구성도 기반으로 정리하기로 함

## 안건 3: 라이센스 및 상용 솔루션 현황

**논의 요약:**
- **상용 솔루션:**
  - 스트리밍 솔루션: 서버 단위 구매, AWS 이전 시에도 재구매 필요
  - OAM(Operation & Management): 서버 헬스체크 및 카메라 자동 절체 기능
  - MHA(MySQL High Availability): DB HA 구성용
- **VPN 어플라이언스:** 
  - 시큐리즈 업체의 전용 장비
  - SSL VPN, PUF VPN 두 종류 사용
  - PUF VPN은 하드웨어 칩(PCI 보드) 내장으로 AWS 이전 불가
  - 카메라 펌웨어와 강결합되어 있어 변경 시 전체 카메라 펌웨어 수정 필요
- **기타:** 스위치, 로드밸런서 등 네트워크 장비 라이센스

**결정사항:**
- VPN 어플라이언스가 AWS 마이그레이션의 주요 기술적 장애물로 확인됨
- 스트리밍 솔루션은 AWS 환경에서도 재구매 필요

**액션 아이템:**

  - 현재 시스템 그대로 AWS 이전 시: 연간 약 160억원 (8년 TCO 기준)

  - 54PB 영상 데이터 이전 현실적으로 불가능

  - AWS 솔루션 활용한 서비스 재설계 검토했으나 비용 문제 미해결
  - 카메라 SD-Card 저장 방식도 검토했으나 백업 용도로만 가능

**결정사항:**
- 2026년 3월까지 DR 방안(AWS vs 온프레미스) CEO 보고 예정
- 비용 효율적인 구조 검토가 최우선 과제
